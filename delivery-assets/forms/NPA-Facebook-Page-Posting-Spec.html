02
OAuth
Not required. Do not build Facebook Login or callback routes for this phase. Publishing uses the existing Page Access Token only.
03
Post to Facebook Page — API route
Implement /api/social/post-facebook — text-only posts (feed) and image posts (photos). Use Graph API v21.0 (or current project version).
// app/api/social/post-facebook/route.ts export async function POST(request: Request) { const { message, imageUrl, scheduledTime } = await request.json() const pageToken = process.env.FB_PAGE_ACCESS_TOKEN const pageId = process.env.FB_PAGE_ID const body: Record<string, unknown> = { message, access_token: pageToken } if (scheduledTime) { body.published = false body.scheduled_publish_time = Math.floor(new Date(scheduledTime).getTime() / 1000) } const endpoint = imageUrl ? `https://graph.facebook.com/v21.0/${pageId}/photos` : `https://graph.facebook.com/v21.0/${pageId}/feed` if (imageUrl) (body as { url?: string }).url = imageUrl const res = await fetch(endpoint, { method: 'POST', headers: { 'Content-Type': 'application/json' }, body: JSON.stringify(body) }) const data = await res.json() return Response.json(data) }
04
Postgres — Prisma ScheduledPost
DB: Prisma model ScheduledPost. New databases: npx prisma migrate deploy (single baseline 20260403120000_baseline from schema). Existing Supabase: run prisma/baseline-truncate-migrations.sql then npx prisma migrate resolve --applied "20260403120000_baseline" — see scripts/prisma-baseline-existing-database.sh. Old migration folders live in prisma/migrations_archive/.
05
Vercel Cron — every minute
Cron fires every minute, loads due pending rows, publishes to Facebook only, sets published or failed.
// vercel.json { "crons": [ { "path": "/api/cron/publish-scheduled-posts", "schedule": "* * * * *" } ] }
// Implemented: GET /api/cron/publish-scheduled-posts — Authorization: Bearer CRON_SECRET // Prisma: findMany ScheduledPost where status=pending AND scheduledAt <= now() // publishToFacebookPage() then update status + fbPostId or errorMsg
